# HEADBANG 2.0 workflows

HEADBANG 2.0 turns the complete roadmap into one shared policy engine for CLI users and MCP agents. High-impact operations follow the same pattern: inspect or plan, review the stable JSON envelope and `planDigest`, enable the relevant permission, execute with `--confirm=<planDigest>`, and inspect the journal if a remote step is partial.

## Native Git Flow bootstrap

```bash
headbang flow status --profile=flow --json
headbang flow init --profile=flow --json
headbang feature start order-flow --profile=flow
```

`flow init` creates missing configured `develop` at the local configured `main` SHA without checkout or push. It never replaces a branch or guesses deleted history. HEADBANG uses ordinary Git and never invokes external `git-flow`.

## Complete release and npm publication

```bash
headbang release plan 2.0.0 --profile=self-release --json
headbang release execute 2.0.0 --profile=self-release --confirm=<digest> --json
headbang package plan --profile=self-release --json
headbang package publish --profile=self-release --confirm=<digest> --json
```

The release transaction handles version sources, notes/changelog, gates, commit/tag, synchronization and atomic push, optional provider release, package publication, artifacts, verification, and journaling. npm publication runs configured tasks, creates one exact tarball, records its SHA-256 digest, authenticates, publishes that tarball, and verifies the registry. It requires `packagePublish.enabled` and `permissions.publishPackage=true`.

`headbang resume <operation-id> --confirm=<original-plan-digest>` completes only provably missing remote/provider/package/artifact steps. Ambiguous local replay is refused.

## Collaboration, onboarding, and extensibility

Provider-neutral change requests support GitHub, GitLab, Bitbucket, and Forgejo with protection inspection and merge strategies. Generated findings require `permissions.publishReview=true` and explicit approval. Delivery sets group destinations; channels name policies such as daily, stable, public, or backend.

`headbang init` previews seven presets before `--write`; config migration makes a backup; credential status reports environment, Git-helper, provider-CLI, and OS-store availability without printing values; recovery only removes provably stale HEADBANG-owned state. Plugins declare API version 1 and typed registries/adapter slots. Workspace releases support unified or independent versions, dependency ordering, package tags, package profiles, and opt-in ordered npm publication with `packagePublish.workspaces=true`. Projection policy preserves or blocks symlinks/LFS and enforces file/byte limits.

MCP exposes typed plans/mutations and read-only resources for redacted config, profiles/channels, status, capabilities, and journals. It accepts no arbitrary shell command. stdout remains JSON-RPC-only.
