---
topic: Native Git Flow bootstrap when develop is missing
updated: 2026-08-19T12:34
---

- (direction) The npm package itself must restore the ability to use native Git Flow; a repository-only workaround is insufficient.
- (constraint) Never install or invoke the external git-flow executable; use ordinary Git through HEADBANG core.
- (capability) CAP-1: Operators can initialize configured Git Flow bases so a missing develop branch is created from the current configured main branch; success is an exact branch SHA match.
- (capability) CAP-2: Repeating initialization is safe and returns already-completed without replacing or resetting an existing develop branch.
- (capability) CAP-3: Humans can initialize through CLI flow init and agents through a typed MCP mutation tool backed by the same core function.
- (capability) CAP-4: Status exposes whether main and develop exist and whether native flow is ready without mutating refs.
- (capability) CAP-5: Windows Git warnings do not replace the actionable error when a Git command fails.
- (constraint) All mutations require permissions.flow=true and a clean working tree; main must already exist.
- (decision) Publish as patch 1.1.4 because this restores an advertised native Git Flow lifecycle that fails after develop is removed.
- (event) Coherence validation passed: every capability has a testable success criterion and no unresolved design choice remains.
- (event) Preservation validation passed: the user direction, package scope, native-only constraint, roadmap update, push, and npm publication requirements are retained.
